Connect to Google Cloud Platform

🌎 Discovery scope

Name the connector and choose what AI Defense looks at. Nothing on this step grants access or creates resources.

Display name for this connector in AI Defense.
Organization
Covers every eligible project, including future ones.
Folder
One folder and its child folders. Use for delegated teams.

Exactly one project. Use for a pilot or regulated workload.

🔐 Authentication method

Choose how AI Defense authenticates to GCP. The generated deployment command configures this credential.

Workload Identity Federation Recommended
Default. AI Defense impersonates a dedicated service account. No long-lived key is stored.
Service Account Key Legacy
Download a JSON key file. Migration from Multicloud Defense or an approved exception only.
Project where the AI Defense service account, workload identity pool, and optional Pub/Sub resources are created.
What AI Defense creates in the deployment project
Always created
Service account — aid-connector@<project>.iam.gserviceaccount.com
Workload identity pool — aid-defense-pool
Workload identity provider — aid-defense-provider

Created only if the matching capability is on
Pub/Sub topic and subscription — aid-audit-events  (requires in-use detection)
Cloud Logging sink — aid-audit-sink  (requires in-use detection)

Nothing is created in the projects being discovered. AI Defense only reads from those.
Service account keys require manual rotation
Google recommends Workload Identity Federation for production workloads. Service account keys are long-lived credentials that must be rotated periodically. Use this option only for migration from Multicloud Defense or when federation is blocked by your security policies.
⚡ Capabilities

Discovery is always on. Validation and in-use detection add permissions to the generated deployment command.

Discover and inventory GCP AI assets Required
Reads Vertex AI and Agent Platform metadata for models, deployments, agents, files, datasets, and RAG corpora.
Enable AI Defense Validation
Adds non-mutating invoke and query permissions for supported endpoints, publisher models, and reasoning engines.
Enable in-use detection
Creates a Cloud Logging sink to Pub/Sub so foundation model usage can be classified as in use.

🚀 Deploy the connector

Run the generated command in your GCP environment. It creates the AI Defense service account, assigns roles at the selected scope, and configures authentication.

⚠️
Sign in to the correct GCP organization and make sure your account has Organization Admin (or Folder/Project Admin for narrower scopes) and Project Creator (if auto-creating the deployment project), then run the command below.
Cloud Shell is the default guided path. One command, scoped to the selections you made in step 1.
Built from your selections and regenerated whenever they change. It grants only the roles the enabled capabilities need.
DEPLOYMENT_PROJECT=aid-security-prod
SCOPE=organizations/123456789012
AUTO_CREATE_PROJECT=true
AUTH=workload-identity-federation
CAPABILITIES=discovery,validation,audit-logs

# Run in Cloud Shell or any terminal with gcloud auth
bash <(curl -sSL https://ai-defense.cisco.com/deploy/gcp/<connector-id>)
Roles this command grants, and why
roles/aiplatform.viewer — Discover GCP AI assets (always on)
roles/aiplatform.user — AI Defense Validation for models and agents
roles/logging.configWriter — In-use detection (audit logs)
roles/pubsub.editor — In-use detection (audit logs)
roles/iam.workloadIdentityPoolAdmin — Creates the pool and provider during deployment only

🔐 Deploy the connector (Service Account Key)

Run the generated command in Cloud Shell. It creates a service account and downloads a JSON key file. Upload the key to AI Defense to complete setup.

⚠️
Sign in to the correct GCP organization. Your account needs Service Account Admin and the relevant role admin permissions at the selected scope.
SCOPE=organizations/123456789012
SA_NAME=aid-connector
CAPABILITIES=discovery,validation,audit-logs

# Creates service account and downloads the key
bash <(curl -sSL https://ai-defense.cisco.com/deploy/gcp/sa-key/<connector-id>)
Upload the JSON key file that the script downloaded. AI Defense encrypts and stores this credential.
